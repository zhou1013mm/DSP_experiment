### 分析

**1. 为什么是“实时”和“分帧”**

实时处理意味着不能等一整段数据收完再算，只能“来一批算一批”。ADC 每完成一个 DMA 缓冲区（`AUDIO_BUFFER_SIZE = 1 KB`，4 通道 × 4 字节，即**每通道 64 点**）就回调一次 `ProcessBuffers()`。64 点刚好是 32 点的整数倍，正好切成 **2 帧**，所以帧缓存跨调用连续累积即可，不需要改缓冲区大小——这就是课上说的“buffer size 是 32 的两倍，不用改”。

帧率 = $f_s / 32$：8 kHz 域是 250 帧/秒（每帧 4 ms），48 kHz 域是 1500 帧/秒（每帧 0.667 ms）。

**2. 实现路线**

沿用 E2 的做法：先 MATLAB 写通算法并用 `fft()` 对照，再逐行移植到 C，最后上板与 ADI 库函数 `rfft32()` 对照。

C 里要专门解决三件事：

- **复数运算**：C 没有复数类型（CCES 也不保证 `<complex.h>` 可用），要自己定义结构体和加减乘；
- **位反序**：MATLAB 里靠矩阵 reshape 折叠实现，C 里要换成下标位倒置的原地交换；
- **权重**：不能每帧现算 `sin/cos`，要预先算好旋转因子表（对应注意事项 (1)）。

**3. 验证方法**

分三层，逐层收紧：

| 层次 | 方法 | 检验什么 |
|---|---|---|
| 算法 | 与 MATLAB `fft()` / `my_fft.m` 逐行移植结果对比 | 递推和位反序有没有写错 |
| 数值 | IFFT 往返、已知单频落在预期谱线 | 正反变换是否互逆、标度是否正确 |
| 上板 | 同一帧数据同时喂给 `my_fft` 和库函数 `rfft32`，逐谱线对比 + 计时 | 定点/浮点实现、编译优化带来的差异 |

## 理论解释

### 基-2 时间抽取（DIT）

DFT 定义：

\[
X[k]=\sum_{n=0}^{N-1}x[n]W_N^{nk},\qquad W_N=e^{-j2\pi/N},\quad N=2^M
\]

把输入按 **偶数点 / 奇数点** 分成两半，长度各 $N/2$：

\[
X[k]=\underbrace{\sum_{r=0}^{N/2-1}x[2r]W_{N/2}^{rk}}_{E[k]}+W_N^{k}\underbrace{\sum_{r=0}^{N/2-1}x[2r+1]W_{N/2}^{rk}}_{O[k]}
\]

再利用 $W_{N/2}=W_N^2$ 和周期性，得到一对“蝶形”公式：

\[
\begin{cases}
X[k]=E[k]+W_N^{k}O[k]\\[4pt]
X[k+N/2]=E[k]-W_N^{k}O[k]
\end{cases}
\qquad k=0,1,\dots,N/2-1
\]

<img src = assets/图片2.jpg >

也就是说：一个 N 点 DFT = 两个 N/2 点 DFT + N/2 次复乘（乘权重）+ N 次复加。对 N/2 继续这样分下去，分 M = log₂N 层就到底了，这就是基-2 时间抽取法（radix-2 DIT）。

### 蝶形运算与运算量

蝶形的形状就是上面那对式子：两个输入、两个输出，中间一个权重 $W_N^k$，形如蝴蝶。每层有 $N/2$ 个蝶形，共 $M$ 层。

| | 复乘次数 | 复加次数 |
|---|---|---|
| 直接 DFT（N = 32） | $N^2=1024$ | $N(N-1)\approx 992$ |
| 基-2 FFT（N = 32） | $\frac{N}{2}\log_2N=80$ | $N\log_2N=160$ |
| 比值 | **12.8×** | 6.2× |

N = 32 时一共只有 80 个蝶形，这也是 C 里三层循环（m / a / b）能跑得很快的原因。

### 位反序

按奇偶不断分组，等价于“把输入下标的二进制位倒过来读”。N = 8 时：

| 原下标（二进制） | 000 | 001 | 010 | 011 | 100 | 101 | 110 | 111 |
|---|---|---|---|---|---|---|---|---|
| 位反序后 | 000 | 100 | 010 | 110 | 001 | 101 | 011 | 111 |
| 值 | 0 | 4 | 2 | 6 | 1 | 5 | 3 | 7 |

所以必须先做一次位反序置换，才能让后面的蝶形（每层都是“相邻两半配对”）直接原地进行，且输出是自然顺序 $X[0],X[1],\dots,X[N-1]$。

在 MATLAB 的 `my_fft.m` 里这是靠反复“对折”实现的：

```matlab
for n = 1:M
    X = [X(:,1:2^(M-n)); X(:,2^(M-n)+1:2^(M-n+1))];
end
```

每折一次，矩阵就从 $2^{M-n+1}\times 2^{n-1}$ 变成 $2^{M-n}\times 2^n$，折 M 次后变成 $N\times 1$ 的列向量，其元素顺序正好是位反序。

### 旋转因子（权重）

$W_{32}^{k}=e^{-j2\pi k/32}$ 具有对称性 $W^{k+16}=-W^{k}$，所以 **32 点只需要存 16 个**（k = 0…15）；又因为 $W^{k}=W^{k\,\text{mod}\,32}$，第 m 层、第 b 个结用的权重是

\[
W_N^{b\cdot 2^{M-m}},\qquad b=0,\dots,2^{m-1}-1
\]

即“表里每隔 $2^{M-m}$ 取一项”，这就是 C 代码里 `step = MY_FFT_N >> m` 的来历。16 个复数 = 128 B，放常量表里，运行时不进 `sin/cos`。

> SHARC 上还会自动启用与 `rfft32` 的对比（见后文），Blackfin 没有 `trans.h`，那部分会自动跳过。

### MATLAB 原型：`class10 FFT/my_fft.m`

先按课件要求用 MATLAB 写通，核心是三件事：reshape 折叠（位反序）→ 加权 → 蝶形。

```matlab
N = length(x1);  M = log2(N);  X = x1;
WN = exp(-j*2*pi/N);

% 预处理：reshape 折叠 = 位反序
for n = 1:M
    X = [X(:,1:2^(M-n)); X(:,2^(M-n)+1:2^(M-n+1))];
end

for m = 1:M
    % step1: 按 2^m 折成“组”
    X_med = zeros(2^(M-m),2^m);
    for a = 1:2^(M-m)
        X_med(a,:) = [X(2*a-1,:), X(2*a,:)];
    end
    X = X_med;
    for a = 1:2^(M-m)              % 组
        for b = 1:2^(m-1)          % 结
            X(a,b+2^(m-1)) = X(a,b+2^(m-1))*WN^((b-1)*2^(M-m));   % 加权
        end
        for b = 1:2^(m-1)
            X(a,b) = X(a,b) + X(a,b+2^(m-1));                     % 蝶形：和
            X(a,b+2^(m-1)) = X(a,b) - 2*X(a,b+2^(m-1));           % 蝶形：差
        end
    end
end
```

注意 step3 的第二行：此时 `X(a,b)` 已经被更新成 $X_1+X_2'$，所以 `X(a,b) - 2*X2` 正好等于 $X_1-X_2'$，与标准蝶形等价（这一点在移植到 C 时特意保持了同样的写法）。

与 `fft()` 对比的脚本是 `script1.m`，性能对比是 `script2.m`（N = 256…4096 时与 `fft()` 的耗时比）。

### C 实现：`my_fft.h`

C 版本是纯头文件（`static inline`，不产生重复定义），和 `my_fft.m` 一一对应。

#### (1) 复数运算

```c
typedef struct { float re; float im; } my_complex;      /* 8 字节 */

static inline my_complex mc_add(my_complex a, my_complex b) { return mc_make(a.re+b.re, a.im+b.im); }
static inline my_complex mc_sub(my_complex a, my_complex b) { return mc_make(a.re-b.re, a.im-b.im); }
static inline my_complex mc_mul(my_complex a, my_complex b)                 /* (ac-bd) + j(ad+bc) */
{ return mc_make(a.re*b.re - a.im*b.im, a.re*b.im + a.im*b.re); }
```

另配 `mc_conj`（共轭）、`mc_abs`（取模，给幅度谱用）、`mc_scale`（乘实系数）。

#### (2) 位反序

不建表，直接用“反向进位”递推：

```c
static inline void my_fft_bitrev(my_complex *X)
{
    int i, j = 0, k;  my_complex t;
    for (i = 1; i < MY_FFT_N; i++) {
        k = MY_FFT_N >> 1;
        while (j & k) { j &= ~k; k >>= 1; }   /* 反向进位 */
        j |= k;
        if (i < j) { t = X[i]; X[i] = X[j]; X[j] = t; }   /* 只换一次 */
    }
}
```

#### (3) 三层蝶形

`my_fft.m` 里 m / a / b 三层循环的直译，`step` 就是权重表的下标步进：

```c
for (m = 1; m <= MY_FFT_LOG2N; m++) {
    half = 1 << (m - 1);        /* 2^(m-1)：每组前/后半长度 */
    span = 1 << m;              /* 2^m    ：每组总长度     */
    step = MY_FFT_N >> m;       /* 2^(M-m)：权重表步进      */
    for (a = 0; a < MY_FFT_N; a += span) {          /* 2^(M-m) 个组 */
        for (b = 0; b < half; b++) {                /* 每组的结    */
            w = MY_FFT_W[b * step];
            t = mc_mul(X[a + b + half], w);         /* 后半乘权重  */
            X[a + b + half] = mc_sub(X[a + b], t);  /* 蝶形：差    */
            X[a + b]        = mc_add(X[a + b], t);  /* 蝶形：和    */
        }
    }
}
```

#### (4) 旋转因子表

`MY_FFT_W[16]`，内容就是 $e^{-j2\pi k/32}$（k = 0…15），编译期常量，运行时零开销：

```c
static const my_complex MY_FFT_W[MY_FFT_HALF] = {
    { +1.000000000e+00f, +0.000000000e+00f },   /* W32^0  */
    { +9.807852804e-01f, -1.950903220e-01f },   /* W32^1  */
    ...
    { +7.071067812e-01f, -7.071067812e-01f },   /* W32^4 = (1-j)/√2 */
    ...
    { +0.000000000e+00f, -1.000000000e+00f },   /* W32^8 = -j */
    ...
    { -9.807852804e-01f, -1.950903220e-01f }    /* W32^15 */
};
```

#### (5) 对外接口

```c
my_fft(x, X);          /* 实数输入  -> 32 点复数谱（自然顺序），分帧时最常用 */
my_fft_cplx(X);        /* 复数输入，就地变换                                 */
my_fft_mag(X, mag);    /* |X[k]|，k = 0..15                                  */
my_ifft_cplx(X);       /* 就地 IFFT（共轭法）                                */
my_ifft(X, x);         /* 复数谱 -> 实序列                                    */
```

IFFT 用共轭法复用 FFT，不单独写逆蝶形：

\[
\text{conj}\big(\text{FFT}(\text{conj}(X))\big)=N\cdot\text{IFFT}(X)
\]

即：先把 $X$ 取共轭 → 走一遍 FFT → 再取共轭 → 乘 $1/N$。

### 分帧与实时化：`adc_dac_playback.c` 的 E3 段

```c
#ifdef FFT_32P
    {
        static float      fft_frame[MY_FFT_N];   /* 分帧缓存，跨调用保持 */
        static int        fft_fill = 0;          /* 已攒了多少点         */
        ...
        for (js = 0; js < nsrc; js++) {
            fft_frame[fft_fill++] = psrc[js * stride];
            if (fft_fill < MY_FFT_N) continue;   /* 还没攒满一帧 */
            fft_fill = 0;

            my_fft(fft_frame, spec);             /* 32 点 FFT    */
            my_fft_mag(spec, mag);               /* 幅度谱       */
            ...                                  /* 存谱线、找峰值 */
        }
    }
#endif
```

几个和 E1/E2 衔接上的细节：

- **不碰 `pFiltered`**：这一段只“看”数据，原有的 FIR/IIR/重采样和播放回环一行都不改；
- **数据来源自动选**：E2 流水线打开时分析 8 kHz 域的 `buf8_filt_work`（每拍约 11 点，约 3 拍凑一帧，谱线间隔 250 Hz）；否则分析 48 kHz 域**第 0 通道**（4 个通道是交织存放的，所以按 `stride = NUM_CHANNELS` 取样，每拍 64 点 = 2 帧，谱线间隔 1.5 kHz）；
- **峰值搜索跳过直流**（k ≥ 1），因为 ADC 有明显直流偏置；
- 若 E1/E2 都没开，把输入直通给 DAC，保证回环还有声音。

### 与 `rfft32` 的并行对比与计时

SHARC 核额外用同一帧数据再算一遍 ADI 库函数（`<trans.h>` 里按点数写死的一族函数，32 点是 `rfft32`）：

```c
START_CYCLE_COUNT(cyc_start);
my_fft(fft_frame, spec);
STOP_CYCLE_COUNT(cyc_my, cyc_start);

START_CYCLE_COUNT(cyc_start);
(void)rfft32(fft_frame, lib_re, lib_im);
STOP_CYCLE_COUNT(cyc_lib, cyc_start);
```

计时用 `<cycle_count.h>` 读 SHARC 的 `EMUCLK` 周期计数器（代码里 `#define DO_CYCLE_COUNTS` 打开该宏），**累计平均**后写入 `time_used[2]`：

```c
time_used[0] = acc_my  / (float)gFftFrameCount;   /* 周期/次 */
time_used[1] = acc_lib / (float)gFftFrameCount;
```

观测变量（CCES 的 Expressions 窗口直接看，也能导出）：

同一帧数据、同一次测量（`time_used` 是全部帧的累计平均）：

| 实现 | 周期/次 | 时间/次 @ 450 MHz | 相对 |
|---|---|---|---|
| `my_fft` | 35968.3 | 79.93 µs | 22.71× |
| `rfft32` | 1584.1 | 3.52 µs | 1× |

### 4. 实时性核算

| 数据域 | 帧周期 | `my_fft` 占用 | `rfft32` 占用 |
|---|---|---|---|
| 48 kHz（本次测量） | 32/48000 = 667 µs | 79.93 µs → **12.0 %** | 3.52 µs → 0.53 % |
| 8 kHz（E2 流水线打开时） | 32/8000 = 4000 µs | 79.93 µs → **2.0 %** | 3.52 µs → 0.09 % |

即使在最不利的 48 kHz 域、未优化的调试构建下，一帧 FFT 也只占用 12% 的帧周期，实时性没有问题。

### 5. 讨论：22.7 倍的差距从哪来

这个比值**不能**读成“自写算法比库函数差 22.7 倍”，主要是三个因素叠加：

1. **编译优化**：测量用的是 CCES 默认的 Debug 配置（`-O0`）。`static inline` 在 `-O0` 下**不会展开**——把 `my_fft.h` 单独编译成汇编可以看到 `my_fft_bitrev` / `my_fft_butterfly` / `my_fft_cplx` / `my_fft` 仍然各自是独立函数（`.type ...,STT_FUNC`），于是每个蝶形里的 3 次复数运算都退化成“压栈传结构体 → 调用 → 取返回值”，80 个蝶形就是 240 次函数调用。改成 `-O1`（或 `-Ov 100`）后这些函数全部被内联：同一个文件编出来的汇编从 `-O0` 的 824 行降到 466 行，`my_fft_*` 也不再作为独立函数出现。

2. **库函数是高度优化的库例程**：`rfft32` 是 ADI 随 CCES 提供的、针对 SHARC 核（双数据取指、零开销循环、延迟槽、并行乘加）专门优化过的实现，寄存器分配和循环开销都压到了最低，不是“普通 C 编译出来的代码”能比的。

3. **接口代价**：`my_fft(x, X)` 还要把 32 个实数搬进复数数组并把虚部清零（32 次写），而 `rfft32(real_in, real_out, imag_out)` 直接吃实数数组。

所以合理的结论是：**算法本身正确且实时（12% 帧周期），速度差距主要来自“未优化的 C + 结构体复数 + 通用实现”对“手写汇编 + 实数专用算法”**。若把工程切到 Release（`-O1`/`-Ov 100`）再测一次，这个比值会明显缩小——这是下一步可以补的一组数据。

另外，本次测量只在 48 kHz 域做了。打开 E2 的 `PIPELINE_48k_8k_48k` 后，E3 会自动改为分析 8 kHz 域（谱线间隔 250 Hz），那时更适合验证 E2 那级 2 kHz 低通的效果。

## 实验结论

1. 用 MATLAB 先写通、再逐行移植到 C 的路线是可行的：`my_fft.h` 在 N = 32 时与 `fft()` 的误差在 float32 舍入量级（1.2e-6），位反序、权重、蝶形三层结构与 `my_fft.m` 完全一致。

2. 上板实测与 ADI 库函数 `rfft32` 的 16 条谱线**逐位相同**（最大绝对误差 0，幅度比 1.000000），说明浮点运算、位反序顺序、标度约定都没有问题；FFT 通路验证通过。

3. IFFT 用共轭法复用 FFT 实现，离线往返验证误差 1.19e-7，`my_ifft()` 可直接用于频域处理（例如在 8 kHz 域做频域低通后再反变换）。

4. 速度上 `my_fft` 是 `rfft32` 的 22.7 倍耗时（35968 vs 1584 周期/次），但原因在实现层面：调试构建未内联、库例程为手工优化实现、通用复数接口还多了一次实数→复数的搬运；而算法复杂度两者是同级的（结果逐位相同已说明是同一个基-2 分解）。实时性上，一帧 32 点 FFT 只占帧周期的 12%（48 kHz）或 2%（8 kHz），满足实时要求。

5. 与课件注意事项的对应关系：旋转因子表、位反序、复数运算三件事都在 C 里显式实现并验证；与 `trans.h`（`rfft32`）的结果和效率对比也已完成，脚本 `compare_fft_trans.m` 可复现。
