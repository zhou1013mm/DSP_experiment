# E5 频域自适应滤波（FDAF）系统辨识 —— 算法与实现设计说明

> 本文是 E5 代码（`adc_dac_playback/fadf.h` + `adc_dac_playback.c/.h`）和
> 验证脚本的唯一算法口径。所有实现与后处理都必须与本文件一致。
>
> 平台：ADSP-SC589 EZ-Kit，SHARC Core1，48 kHz，4 通道，每次音频回调
> 每通道 64 帧（1.333 ms）；每 4 次回调组成一个 **256 点处理块**
> （5.333 ms）。

---

## 1. 实验目标（对应 PPT）

1. 用 FDAF 辨识一个"未知"线性系统（预设参数的 FIR），得到其**时域冲激响应**
   \(\hat h(n)\) 和**频域响应** \(\hat H(f)\)，与真值比较。
2. 复习重叠保留法（Overlap-Save）：帧长 \(N=512\)、帧移（hop）\(L=256\)。
3. 实现**梯度约束操作**（constraint operation）并与不约束版本比较。
4. 进阶：**分区 FDAF**（Partitioned FDAF），总长 1024 点 = 4 个 256 点分区；
   与"标准 FDAF（1024 点，2048 点 FFT）"比较**计算效率**与**系统延迟**。

---

## 2. 信号约定

* 采样率 \(f_s=48000\) Hz。
* 激励 \(x(n)\)：**宽带白噪声**（DSP 内部产生，固定种子，
  xorshift32 均匀分布再乘 0.5，即 \(x\in[-0.5,0.5)\)，\(\sigma_x^2\approx1/12\)）。
  内部一律用 float 计算；送 DAC / 存盘时再乘缩放系数。
* "未知"系统：预设参数的 FIR \(h_{\text{true}}\)，长度 256（基础）或 1024（进阶）。
* 期望信号：\(d(n)=h_{\text{true}}*x(n)\)（在 DSP 内用重叠保留法精确算出）。
* 自适应滤波器输出 \(y(n)\)，误差 \(e(n)=d(n)-y(n)\)。

### 2.1 两个预设的未知系统（deterministic）

单位：\(h\) 归一化到 \(\sum_n |h(n)|=0.9\)（保证 \(|d(n)|\le 0.9\max|x|\)）。

**系统 A（基础模式，256 点）—— "带共振的短混响"**

```
h_A(n) = 0.70*delta(n-2)
       + 0.35*exp(-(n-2)/40.0)*cos(2*pi*1800*(n-2)/48000) * u(n-2),   n = 0..255
```

（即主径 + 1.8 kHz 阻尼谐振尾。）

**系统 B（进阶模式，1024 点）—— 类"房间"混响**

```
h_B(n) = 0.60*delta(n-2)
       + exp(-(n-2)/150.0)*u(n-2)*r(n),   n = 0..1023
```

其中 `r(n)` 为固定种子（0x1234567）的 xorshift32 零均值伪随机序列
（均匀，幅度 1），再整体归一化。前 2 点（n=0,1）为 0，即 2 点纯延迟。

> 两个系统的参数（延迟、衰减、频率、增益、种子）都以宏写在 `fadf.h`，
> 属于"预设参数构建未知线性系统"。

---

## 3. 标准 FDAF（基础）

块长 \(L=256\)，FFT 长 \(N=2L=512\)。第 \(m\) 块：

```
xf_m = [ x_{m-1}(0..255) , x_m(0..255) ]        (512 点重叠保留帧)
ef_m = [ 0 (256 个零)    , e_m(0..255) ]        (误差帧：前半零填充)

X_m = FFT(xf_m),  E_m = FFT(ef_m)

y_m = IFFT( X_m .* W ) 的【后 256 点】            (有效线性卷积)
e_m = d_m - y_m

g   = IFFT( conj(X_m) .* E_m )                   (循环相关)
约束： g(0..255) 保留， g(256..511) = 0            (只保留物理冲激响应部分)
Gc  = FFT(g)
W  <- W + mu * Gc                                 (约束版)
     W  <- W + mu * (conj(X_m).*E_m)              (不约束版，仅用于对比)
```

**误差帧为什么前半补零**：`IFFT(conj(X)E)[k] = sum_n xf[n]·ef[(n+k) mod 512]`，
只有 `ef = [0, e_m]` 时前 256 点才严格等于逐点梯度
`g[k] = sum_{i=0}^{255} e(mL+i) x(mL+i-k)`（主机端参考模型用逐点定义对拍：
相对误差 8.6e-8；若按最初写法的 `[e_{m-1}, e_m]`，误差 1.0，多出与旧误差的
互相关项）。**结论：`ef=[0,e_m]`，不需要保存 e 历史。**

自适应滤波器长度 = 256 点（W 的时域等效 = IFFT(W) 的前 256 点）。

---

## 4. 分区 FDAF（进阶）

总长 1024 点 = \(P=4\) 个 256 点分区。仍用 \(N=512\)、hop=256：

```
Y_m = sum_{p=0}^{3} X_{m-p} .* W_p          (每个 W_p 对应 256 taps)
y_m = IFFT(Y_m) 的后 256 点
e_m = d_m - y_m

每个分区独立做梯度约束：
  G_p = conj(X_{m-p}) .* E_m
  g_p = IFFT(G_p);  g_p(256..511)=0;  Gc_p = FFT(g_p)
  W_p <- W_p + mu * Gc_p                    (约束版)
  W_p <- W_p + mu * G_p                     (不约束版，对比用)
```

* 分区 FDAF 延迟 = 256 点 = **5.33 ms**；
* 标准 FDAF 若要 1024 点，必须 \(N=2048\)、hop=1024，延迟 = 1024 点 = **21.33 ms**，
  且每块 5 个 2048 点变换。两者都在启动 benchmark 里实测 cycles。

## 6. 启动 benchmark（E5_Init，在音频启动前运行）

用同一段白噪声激励，对 5 个变体各跑 `E5_BENCH_BLOCKS` 块，记录：

| 变体 | 说明 | 延迟 |
|---|---|---|
| 0 | 标准 256 点，**约束** | 5.33 ms |
| 1 | 标准 256 点，不约束 | 5.33 ms |
| 2 | 分区 1024 点，**约束** | 5.33 ms |
| 3 | 分区 1024 点，不约束 | 5.33 ms |
| 4 | 标准 1024 点（N=2048），约束 | 21.33 ms |

每块用 `cycle_count.h` 计 cycles；每块记 MSE(dB)；
跑完后由 W 求时域 \(\hat h\)，算失配
`mis = 10*log10( sum((hhat-h)^2) / sum(h^2) )` dB。
benchmark 结束把状态清零，正式音频重新开始。

## 7. 实时链路（ProcessBuffers，每 4 次回调一个块）

每个块（4 次回调）分成 4 个阶段，每次回调只做 1 个阶段，保证单次回调
计算量不超过 DMA 的 ping-pong 期限（约 2.66 ms）：

| 阶段 | 工作 | 变换数 |
|---|---|---|
| S0 | 生成/收集 256 点白噪声 x_m；组 xf_m；FFT -> X_m | 1 |
| S1 | 算 D=Σ X_{m-p}Htrue_p、Y=Σ X_{m-p}W_p；打包 IFFT(Y+jD) 得 y_m,j d_m；e=d-y；组 ef_m；FFT -> E_m | 2 |
| S2 | G_p=conj(X_{m-p})E；IFFT、约束、FFT、更新 W_p | 2 |
| S3 | 空闲（输出 FIFO 续流 + 计数/采集） | 0 |

* 输出 \(e(n)\) 送 DAC（听感上：白噪声误差逐渐收敛变小）；
* 采集/导出用**内部** x(n)、d(n)、e(n)（不经过 DAC/ADC 模拟链路，
  避免模拟增益/延迟污染辨识结果）；ADC/DAC 回环只用来证明实时链路在跑
  (`AdcCount` 增长、`bEventError=0`)。
* 实时学习曲线：每块记 1 个 dB 值，最多 512 点。
* 每块 cycles 记录到 `gE5Debug`，第一块/平均/最大 cycles 进 `gE5Timing`。

## 10. 验证（无硬件时的必做项）

1. **SHARC 指令集模拟器**：把 `fadf.h` 编成独立测试程序，在 CCES
   SC589 SHARC 模拟器上跑 sweep，导出 `gE5Hhat / MSE / cycles`，
   用 Python 后处理确认收敛与失配。
2. **主机端参考模型**：Python(float32) 独立实现同一算法，
   与模拟器结果对拍；并验证约束操作"保留前一半"的正确性
   （与逐点时域梯度逐点比较）。
3. **编译/链接**：用工程自带 `make` 全量编译，确认无 warning、
   链接不 out-of-memory。
