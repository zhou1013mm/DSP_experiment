> 因为 E5 的工作区 + 采集数组一共约 240 KB，默认 LDF 的 block0 放不下，

## 3. 宏开关（`adc_dac_playback.h` 末尾）

默认已经配好：

```c
// E5
#define E5_FADF                /* 打开 E5 */
//#define E5_MODE_STD          /* 基础模式：标准 FDAF，N=512，256 点模型 */
#ifndef E5_MODE_STD
#define E5_MODE_PART           /* 进阶模式（默认）：分区 FDAF，1024 点 = 4×256 */
#endif
//#define E5_NO_CONSTRAINT     /* 实时链路改用“不约束”频域更新 */
//#define E5_PART_CONSTRAIN    /* 分区模式实时用约束版（Debug 下太慢，需 Release） */
```

**想采两组数据（推荐，对应 PPT 基础 + 进阶）**：

| 数据组 | 宏设置 | 实时跑什么 | 数据目录 |
|---|---|---|---|
| 进阶 | 默认（`E5_MODE_PART`） | 1024 点分区 FDAF（不约束实时更新） | `data_part/` |
| 基础 | 去掉 `E5_MODE_STD` 的注释、注释掉 `E5_MODE_PART` | 256 点标准 FDAF（**约束**版实时） | `data_std/` |

两种模式下，启动 benchmark 都会把 5 个变体（标准256约束/不约束、分区1024约束/不约束、
标准1024 N=2048 约束）的 cycles/学习曲线/失配一起测出来，所以两次导出的
`gE5BenchMSE` / `gE5Timing[0..7]` 是一样的。

## 5. 运行与看现象

1. 下载、全速运行（**不要设断点**，E5 启动阶段会先跑约几秒 benchmark）。
2. Console 先打印：
   ```
   E5 code version=20261119, mode=1024, constrain=0, mu=6.00e-03
   E5 bench cycles/block: std256C=... std256U=... partC=... partU=... big1024C=...
   E5 bench misalign dB: std256=... part1024=... big1024=...
   ```
   再打印 `E5 capture start: AdcCount=...`，约 250 ms 后打印
   `Capture complete ...`，以及：
   ```
   E5 realtime: mode=1024 constrain=0 blocks=... cycles/block avg=... first=... max=...
   E5 misalign: std256=... dB  part1024=... dB  big1024=... dB
   ```
3. 判断跑没跑起来（AGENTS.md §4 诊断顺序）：
   - `AdcCount` 必须持续增长；`bEventError` 必须是 0；否则先看 `gE5Debug`。
   - `gE5CodeVersion` 必须是 20261119（否则编的是旧源码副本）。
   - `gE5Debug[0]` 进入 E5 次数、`[1]` 块数、`[2]/[3]/[4]/[5]` 分别是 S0/S1/S2/S3
     阶段执行次数（正常约 1:1:1:1 增长）、`[6] AdcCount`、`[7] DacCount`、
     `[8] bEventError`、`[10]/[11] 采集状态`。
   - `gE5Timing[8]` 是实时块平均 cycles（450 MHz：5.333 ms = 2.4M cycles），
     `[14]` 第一块、`[15]` 最大块。**每个阶段（S0/S1/S2）都不应超过约
     1.2M cycles（2.66 ms）**，否则 DMA 会饿死。
4. 若 `AdcCount` 卡在 6 左右、`bEventError=1`：实时块超时。依次尝试：
   1. `E5_MODE_STD`（每块 5 次 512 点变换、分 3 个阶段，比分区约束版轻）；
   2. 编译 **Release**（或给 Debug 加 `-O2`）；
   3. `#define E5_NO_CONSTRAINT`（每块省 2 次变换）。
   分区约束版（`E5_PART_CONSTRAIN`）在 Debug -O0 下每块 11 次变换 > 5.33 ms，
   **只能 Release 下实时跑**；它仍然会在启动 benchmark 里被测量。

## 6. 导出数据

`Capture complete` 之后（程序会停在断点/结束），在 CCES 的 Expressions /
Memory 窗口选中下列变量，右键 **Export**，格式选 **8-bit hex / 每行一个字节**
（与 E4 一致；`e5_postprocess.py` 的读取器同时支持 hex 和十进制）。

放到 `D:\DSP_experiment\E5_FADF\data_part\`（基础模式用 `data_std\`），文件名必须一致：

| 变量 | 类型/长度 | 文件名 | 内容 |
|---|---|---|---|
| `gE5Hhat` | float[1024] | `gE5Hhat.dat` | 辨识出的时域冲激响应 |
| `gE5HtrueT` | float[1024] | `gE5HtrueT.dat` | 未知系统真值 |
| `gE5Timing` | float[16] | `gE5Timing.dat` | cycles/失配/mu/模式（下标见设计说明 §9） |
| `gE5Debug` | uint32[16] | `gE5Debug.dat` | 调试计数 |
| `gE5BenchMSE` | float[1500] | `gE5BenchMSE.dat` | 5 个变体学习曲线（5×300） |
| `gE5RtMSE` | float[512] | `gE5RtMSE.dat` | 实时学习曲线 |
| `gRawCapture` | int16[12000] | `gRawCapture.dat` | 内部 x(n)，250 ms |
| `gProcessedCapture` | int16[12000] | `gProcessedCapture.dat` | 内部 e(n)，250 ms |
| `gProcessed1024Capture` | int16[12000] | `gProcessed1024Capture.dat` | 内部 d(n)，250 ms |

> int16 数组的导出长度按“字节数”选：12000 个 int16 = 24000 B；float 数组
> 1024 个 = 4096 B、1500 个 = 6000 B、512 个 = 2048 B、16 个 = 64 B、256 个 = 1024 B。
> 若导出长度选多了，脚本会按约定长度截断；选少了对应图会报错/跳过。

## 8. 预期结果（主机端参考模型，`analysis_host/REF_MODEL_NOTES.md`）

| 变体 | mu | 300 块失配 | 首次 ≤ -25 dB |
|---|---:|---:|---:|
| 标准256 约束 | 8e-4 | -44.8 dB | 168 块 |
| 标准256 不约束 | 8e-4 | -44.9 dB | 168 块 |
| 分区1024 约束 | 8e-4 | -43.3 dB | 173 块 |
| 分区1024 不约束 | 6e-3 | -28.0 dB | 148 块 |
| 标准1024(N=2048) 约束 | 2e-4 | -44.6 dB | 167 块 |

- 实时默认模式（分区 1024 不约束）在 2 s warmup（≈375 块）内应已收敛，
  250 ms 采集里 `e/d` RMS 比例应在 -30 dB 量级；
- `gE5BenchMSE` 里第 0 块是 0 dB 附近，随块数下降；
  第 5 个变体（下标 4）只有前 150 块有效，其余为 0；
- 若模拟器/DSP 结果与上表差 > 1 dB，按参考模型 NOTES §6 的顺序查：
  E 帧是否零填充、约束是否保留前一半、d/y 是否同相。
